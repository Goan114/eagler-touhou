# TH15 多人资源加载前释放回滚缓存

报告 `20261028T122634968Z-99fced` 来自主站双人回滚对局。用户补充：正篇接近 Boss、尚未开打，具体关卡未知。

## 分配失败位置

使用原发布对象重新链接并导出符号表，WASM SHA-256 与报告的 `dfcb9969c623d71b905b4ac7e2b18d2e94752b31c72f66e8c28ec7db87e1223c` 完全一致。首个错误的调用链为 `ApplicationState::complete_loading → StageAssets::load → load_animation → AnmManager::load → vector<unsigned char> 缓冲分配 → operator new → abort`。后续停止保存时的异常发生在这次分配失败之后。

报告的线性内存大小为 1 GiB，等于该版本的配置上限；这一数值表示线性地址空间大小，不是仍在使用的堆对象总量。报告没有记录本次分配请求的字节数或快照的实时占用，具体关卡也无法由现有记录确定。[证据摘要](evidence.json)保留了定位所需的构建身份和栈位置。

## 缓存生命周期

每帧确认后的 `discard()` 保留快照容器，便于战斗中复用。资源加载此前也沿用这些高水位缓存，新关卡资源分配会与旧快照缓存叠加。

在普通加载循环、旁观确认帧加载路径和对局缓存重置处，释放同时满足 `valid == false`、`captured == false` 的快照对象。有效日志和仍保留的推测图像继续用于回滚。加载路径保留网络帧序号、提交位置和重演位置；常规战斗确认仍复用缓存。变更归属 `ports/th15-mp`。
