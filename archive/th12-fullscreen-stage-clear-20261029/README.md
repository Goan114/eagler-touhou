# TH12 全屏切换与关底预热

TH12 普通版和多人版在全屏／窗口尺寸变化后，从下一次显示回调重新建立本地计时信用，避免浏览器切换期间的停顿集中变成补帧任务。输入清理保留按资源、年龄与参数确定的动画采样缓存；核心帧号、碰撞和联机输入时间线由原有逻辑继续管理。帧率计数仍接收真实显示回调时间。

THPrac 开启、正常流程中没有可见原生控件时，覆盖画布不再每帧清空 WebGL 或读取布局，并从页面合成中隐藏。打开原生工具窗口时重新显示并更新布局；最后一个可见窗口关闭后清掉旧内容一次。

关底结算预热下一面的贴图，每次显示帧之后提交一张。前台加载继续使用原来的并行路径。真实四面到五面、五面到六面预热采样中，一次显示帧内最多上传数分别从 13、16 张降到 1 张。候选的总预热时间约 652、540 ms，分布在原有结算阶段；加载尚未完成时，现有换面路径继续等待资源。

## 验证范围

- 普通与多人渲染套件各 86、88 项，覆盖输入清理、视口时钟重置、采样前后跳转、纹理上传让帧，以及空 THPrac 画布的退场与恢复。
- 真正执行浏览器帧循环的协议与录像速度测试，覆盖持续过载时仍发布新画面、录像变速与 THPrac 开关。
- 使用生产 Wasm、真实四／五面终符进入结算。下一面资源预热前后的呈现端点完全一致，RGBA 像素差异为 0，WebGL／浏览器无错误。
- Chromium 中开启 THPrac，Backspace 打开和关闭原生工具窗口，画布隐藏状态依次为 true、false、true；随后执行两轮全屏进入／退出。

本机 Chromium 软件渲染复测覆盖全屏按钮对应的 Fullscreen API 和 THPrac 正常游玩路径。基线和候选均未复现用户设备上持续 5–10 秒的 5 FPS，或结算固定 50 FPS，因此这里的通过项证明上述成本已经移除、画面及控制行为保持一致，设备上的最终改善需要同场景复核。

[预热基线](paired-before.json)、[预热候选](paired-after.json)、[THPrac 全屏候选](fullscreen-after.json)记录单次本机结果。预热浏览器脚本比较的核心与资源来自既有 `rollback-th12-performance` 本地产物，不是跨设备性能承诺。两个目录中的实现分别归属于普通版与多人版。

[源码归属记录](source-scope.json)对应两侧目录投影与输入文件身份。沿用户要求保留独立的日常修复历史，投影分支用于核对，不将投影父链接回本修复分支。
